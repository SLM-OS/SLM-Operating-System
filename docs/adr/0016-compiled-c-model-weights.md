# ADR 0016: Policy model weights are compiled into the kernel image, with runtime blobs as an override

Status: accepted (backfilled).

## Context

The AI scheduler (MLP and PPO, 108 -> 256 -> 256 -> 128 -> 42) and the AI
eviction policies (XGBoost, MLP) are trained outside this repository: the
scheduler in the sibling `slm-os-scheduler-ai` project ("Plan A",
`scripts/import_ai_weights.sh`), eviction in `slm-os-page-sim`
(`scripts/import_eviction_weights.sh`). The kernel needs the trained values
at the point a policy is registered, on every platform including QEMU.

## Decision

- Trained weights enter the build as generated source and are compiled
  into `slmos.elf` as `const` arrays:
  - Scheduler: `kernel/sched/ai/ai_weights_mlp.c`, `ai_weights_ppo.c`
    (C99 hex-float `const float`, 64-byte aligned, "Auto-generated by
    export_models.py"), declared in `ai_weights.h`; optional
    `ai_weights_*_real.c` variants. All-zero `ai_weights_stub.c` allowed
    development before Plan A delivered.
  - Eviction: Rust in `runtime/src/mm/eviction/generated/`
    (`xgb_policy_generated.rs`, `mlp_policy_generated.rs`,
    `mlp_policy_f32.rs`) with `*_stub.rs` fallbacks.
  - Cold-boot GPU eviction pipeline: `cmake/gen_eviction_mlp_weights.cmake`
    turns `mlp_policy_f32.rs` into a C header for
    `kernel/gpu/nvidia/ga10b_eviction_weights.c` at build time, with no
    Python in the build.
- Build flags select the set: `AI_SCHED` (Makefile; ON for RASPI5 and
  JETSON_ORIN_NANO, OFF elsewhere; CMake `ENABLE_AI_SCHEDULER`),
  `AI_WEIGHTS=synthetic|real` (#884; per #848 both are options and
  "switching is build-time, not runtime"), and `EVICTION_MODELS`.
- Since d5304f5c "Add runtime-loaded policy model workflows" (2026-04-25)
  the policy code stays compiled in while parameters can also be loaded at
  run time (`kernel/sched/ai/runtime_model.c`, eviction blobs, autoload).
  An activated runtime model wins; the compiled-in arrays are the default
  and the fallback (`ai_inference.c`; `docs/eviction-xgboost-graduation.md`
  "Baked ... Default ship config; no SD-card files needed").
- MNIST is embedded too, but as the ONNX file, not as C: `include_bytes!`
  of `models/test/mnist.onnx` in the runtime, and `.incbin` in
  `kernel/src/mnist_gpu_embed.S` for the cold GPU pipeline (#1088).

## Alternatives considered

- Why compiled-in arrays were chosen over runtime loading in April 2026:
  unknown, ask the user. The phase records (12f6e307, 251d6745,
  `docs/archive/todos/TODO - PHASE AI-Sched.md`) describe the mechanism
  but give no reason.
- Runtime-loaded parameters only: not adopted. The dynamic loading plan
  (`docs/archive/plans/dynamic-policy-model-loading-plan.md`) added
  loadable parameters beside the compiled-in ones, with "safe fallback"
  as a stated requirement; the XGBoost scheduler cascade (~9 MB, #855) is
  the one model that is runtime-only (`runtime_model.h`).

## Consequences

- A policy works on a fresh boot with no files on any medium.
- New weights in the default path need a regenerate, rebuild and redeploy;
  the generated sources are large (each scheduler file is about 3.1 MB of
  text).
- Paths that read the compiled-in arrays directly ignore an activated
  runtime model: the GA10B scheduler GPU path did (#1113).
- Promoting a runtime blob to the default is a procedure with its own
  on-device equivalence check (`docs/eviction-xgboost-graduation.md`, #952).
