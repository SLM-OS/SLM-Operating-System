1. **C0 reuses PR #1208.** PR #1208 (opened by the earlier session that ran
   the run-1 follow-up) already carries #1194, #1197 and #1198 with
   pi-5-1 and both Jetson paths at 10/10. Opening a second branch with the
   same three fixes would split the review. C0's builder therefore: (a)

   reports gaps without rewriting the branch; (b) writes #1196 as a new

   (c) rebases the removal branch onto `fix/boot-path-1193`. #1208 stays in
   its current non-draft state: the brief's "draft PRs only" governs PRs
   this run opens, and changing the state of a PR the user already has open
   is the user's call. Recorded as a deviation.
2. **#1197 approach as found in #1208:** invalidate by VA over the
   caches-off range in `mmu_enable` before SCTLR.C=1, rather than zeroing
   the task table with caches on or cleaning to PoC. A clean would write a
   stale dirty line over the caches-off store; an invalidate discards it.
   The C0 critic checks this against the brief's wording ("state which and
   why").
3. **#1204 scope.** The issue body says the pre-rebase UEFI run's raw rows
   were never saved (only a hand-written summary showing 463 to 602 ms

   is the evidence branch based on c69438a2.
4. **`NC_AXIS=OFF` exists only on `c3-hw-1193` @ 10f8688e.** C2's
   `NC_AXIS=OFF` cell is built from that commit with C2's instrumentation
   applied as a patch, so all three cells carry identical instrumentation.
5. **Log ownership.** Builders and critics do not edit this file. They
   return their entries; the orchestrator appends them with attribution.
6. **Removal-branch writes are serialized** in this order: C0 rebase onto
