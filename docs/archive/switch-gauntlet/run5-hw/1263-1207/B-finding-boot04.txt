What follows from the observations
 - The block's header read intact at the walk after test_suite_oplib_gpu_as and read zero at the walk after
   test_suite_gpu. That bounds when the CPU's view of those bytes changed. When the bytes changed in DRAM is not bounded
   from below: a device that does not snoop the CPU caches can write DRAM under a line the CPU still holds, and a header
   the PMM wrote can be lost from the cache without being written back (DC IVAC discards dirty lines); in both cases
   the walks keep reading the cached copy until the line leaves the cache, and then read DRAM.
 - So the capture does not exclude a write before test_suite_gpu, including the window in which Linux's xHCI controller
   is still running. It excludes that window only for a write the CPU would have seen at once.
 - What reads zero: both links, and at least the last 64 bytes of the block before and the first 64 of this one. The
   extent is not known beyond those 128 bytes. That the block is 64 KB at a 64 KB boundary says nothing: every order-4
   block is.
 - block_state[] still marked the block as a listed order-4 head, so no list operation of the allocator had taken it.

Candidates (none shown)
 - The MNIST GPU path that the suite's last tests start on the inherited channel: the GPU writing into a page the
   hand-off reservation does not cover, or SLM-OS code on that path clearing a buffer.
 - A device left running by Linux across kexec (xHCI, GPU) that wrote the page earlier, seen when the cached line was
   dropped.
 - A lost header write: test_suite_gpu is also the suite that issues DC IVAC (kernel/gpu/cache.c:84-98) from three
   tests; the call sites as written cover only the tests' own pages (B-ivac-callers.txt), so this is not shown either.
 - Whether the once-a-second tick walk runs on this board was not checked separately; the finding came from the suite
   boundary walk.
 - The two earlier halts of this session (f55c5293 boot01 order 7, boot05 order 5) show a list ending after one or two
   pops and nothing more; they have no dump.
