# C2 step 3 procedure (jetson-nano-2), head c1/1213-fix @FULL@; written before the lab hand-off, nothing run yet
# boot banner: n/a (procedure, not a run)

Artifacts (make kernel-clean; make kernel PLATFORM=JETSON_ORIN_NANO, in
the l4-c2 worktree at @SHORT@, build exit 0; CMakeCache
ENABLE_WORK_STEALING=ON, JETSON_HW_TICK=ON, SECONDARY_PREEMPT=ON; the
commit string @FULL12@... is in the ELF):
- slmos.elf (kexec) sha256 @ELFSHA@
- slmos.bin (UEFI)  sha256 @BINSHA@
Snapshotted in the C2 scratchpad (jetson/@SHORT@/). If the orchestrator
hands over a different head, rebuild and replace these two lines first.

Helper scripts (ssh to the board's SD Linux only; no labctl inside):
tools/v2/j_stage.sh.txt, j_kexec.sh.txt, j_esp.sh.txt.
All hardware actions go through the labctl MCP tools.

## 0. Pre-flight (first labctl calls, only after the hand-off message)
1. run_health_check(jetson-nano-2): record the starting power state.
2. list_claims: C3 must have released the board.
3. bindings_list + actuation_status for every binding:
   recovery_mode must be deasserted.
4. claim_sbc(jetson-nano-2, 120 min, reason "lifecycle run 4 C2 step 3",
   agent_name c2-builder). Renew before 100 min.
5. Board IP from the lab://sbcs resource.

## A. kexec: 20 x bench stealing --sustain 2500 --assert-shares
1. Linux up: if the console is not SD Linux, power_cycle and
   serial_capture(timeout 150, until "login:").
2. j_stage.sh <ip> slmos.elf slmos-c2-@SHORT@.elf: copies to
   /root/slmos-c2-@SHORT@.elf, syncs and compares the sha256 (stop on
   a mismatch). /root/slmos.elf is never touched, so no backup or restore
   of the shared default kernel is needed.
3. j_kexec.sh <ip> slmos-c2-@SHORT@.elf: plain `slmos-kexec` (default
   cpufreq pin, channel-preserving helper), detached.
4. serial_capture(timeout 150, until "slmos>|PANIC|panic|Unhandled
   Exception") -> file kexec-assert-boot.txt.
5. serial_send "cat /sys/version" (capture_until "slmos>", 10 s):
   commit must read @SHORT@. Re-send once if the reply is empty or
   belongs to the previous command (known Jetson post-kexec slip).
6. Runs 01..20, same boot, one file each (kexec-assert-runNN.txt):
   serial_send "bench stealing --sustain 2500 --assert-shares",
   capture_until "slmos>", capture_timeout 60.
   Per-run pass criterion (docs/work-stealing-bench.md, #1216/#1227;
   steal_shares_check(), owner CPU 1, thieves CPUs 0,2,3,4,5): the line
   "ASSERT-SHARES: PASS". FAIL is any of: a thief's share below half of
   the best thief's share, no thief executed a task, or a timeout (30 s
   after the supply ended); each prints "ASSERT-SHARES: FAIL ...".
   Recorded per run: the verdict line, lowest/best thief share and their
   ratio, the per-CPU distribution, and the c2t/iw lines.
   Cell result: n/20 PASS, plus the lowest-to-best ratio range.
   A panic or a missing prompt (reply without "slmos>") ends the cell
   and is reported as such, with the capture.

## B. kexec boot test, 10 boots (boot_test cannot kexec; manual loop)
For NN = 01..10: power_cycle -> serial_capture(150 s, "login:") ->
j_kexec.sh <ip> slmos-c2-@SHORT@.elf (file already staged) ->
serial_capture(150 s, "slmos>|PANIC|panic|Unhandled Exception") ->
file kexec-boot-runNN.txt. PASS = "slmos>" within 150 s with no
panic or Unhandled Exception in the capture. Report n/10 and the
failure pattern.

## C. UEFI-direct boot test, 10 boots (docs/deploy/jetson-uefi-direct.md)
1. power_cycle to SD Linux. j_esp.sh <ip> check (fsck.vfat -n and the
   current \EFI\SLMOS\SLMOS.efi sha256 from a read-only mount), then
   j_esp.sh <ip> backup <scratch> (as-found copy). File:
   uefi-esp-asfound.txt.
2. Boot 01: scripts/jetson-uefi-deploy.sh <ip> <scratch>/slmos.bin
   (writes the ESP once, verifies the sha256, sets BootNext to "SLM-OS
   NVMe", reboots) -> serial_capture(120 s, "slmos>|Unhandled
   Exception|Powering off|ABORT") -> uefi-boot-run01.txt; then
   serial_send "cat /sys/version" (commit @SHORT@).
3. Boots 02..10: power_cycle (BootNext was consumed, so SD Linux) ->
   j_esp.sh <ip> bootnext (no ESP write) -> the same serial_capture
   -> uefi-boot-runNN.txt. Before boot 02, j_esp.sh <ip> check once more
   (fsck -n clean and the sha256 equals slmos.bin's after the write,
   per #1187).
   PASS = "slmos>" within 120 s with none of the failure patterns.
4. Restore: power_cycle to SD Linux, j_esp.sh <ip> restore
   <scratch>/SLMOS.efi.asfound (sha256 must equal the as-found one;
   fsck -n clean). File: uefi-esp-restore.txt.

## D. Leave the board as found
- ssh rm -f /root/slmos-c2-@SHORT@.elf; sync (board at SD Linux).
- If it started powered off, power_off.
- release_sbc(jetson-nano-2).

## Time budget (estimate)
Pre-flight 3 min; A about 10 min (boot 4 min, 20 x ~15 s);
B about 40 min (10 x ~4 min); C about 30 min (10 x ~2.5 min plus ESP
steps); D 3 min. About 90 min; claim 120.
