  vector saw SP 0 (orig sp=0x0, ESR 0x96000045, FAR 0xffffffffffffffd0, ELR task_entry_trampoline).
- Sequence A (3 of 3; also qemu-1213-stresstrace-multi-run01), slot 6, gens from run04:
  1. CPU 1 runs id 188 (gen 159): EXIT, TERMINATE (state 3) under CPU 1's rq_lock.
  2. CPU 0 (test, wait returned) DESTROY slot 6: gen 159 -> 160, while CPU 1 is still in
     schedule() for it (CPU 1's ZOMBIE_SET is the next record, its SWITCH out two later).
  3. CPU 1 ZOMBIE_SET slot 6 (gen already 160), SWITCH to idle (slot 1), idle ZOMBIE_REAP.
  4. CPU 0 CREATE_ALLOC slot 6, id 189 (task_lock section sets only id; state still 3).
  5. CPU 1 (reaper) DESTROY passes the TERMINATED check, clears id/stack_base/stack_top:
     gen 160 -> 161 (DESTROY b=stack_base 0x0: CPU 0 had not stored it yet).
  6. CPU 0 CREATE_CTX_DONE reads back ctx.sp = 0x0 (task_create copies stack_top after the
     reaper cleared it), x19 = latency_task_entry, x30 = task_entry_wrapper; ADD to CPU 1.
  7. CPU 1 SWITCH into slot 6 gen 161 id 0 with in.ctx.sp = 0x0 -> fault at the first stack
     store in task_entry_trampoline.
  Run 3's hypothesis (switch_to reading a half-written context) is not this: the context was
  complete; its sp field held 0 because the second destroyer had cleared stack_top.
- Sequence B (qemu-1213-stresstrace-multi-run02, panic path dump, `task_exit: schedule
  returned!`; merged in qemu-1213-stresstrace-merged.txt), slot 6:
  1. CPU 1 id 188 (gen 163): EXIT, TERMINATE, ZOMBIE_SET; not yet at switch_to.
  2. CPU 0 DESTROY (163 -> 164), CREATE id 189: CREATE_CTX_DONE ctx.sp 0x42c40000 (stack top),
     x19 slot_reuse_entry; ADD to CPU 1.
  3. CPU 1 SWITCH out of slot 6 (gen 163 recorded) about 45 us after CTX_DONE: switch_to's save
     half writes id 188's registers into slot 6's context, over id 189's.
  4. CPU 1 SWITCH into slot 6 gen 164 id 189: in.ctx.sp 0x42c3ff50, in.ctx.x19 0x407eb180
     (id 188's saved schedule() frame, not a task_create image); SWITCH_RET; the task returns
     into id 188's task_exit -> panic.
- Both: a slot is reclaimed while the CPU that ran it is not finished with it (B), and a second
