# x86-gpu-trace

Tooling used to investigate how nouveau unlocks SEC2 on GA10x. Outputs
and conclusions live in
`docs/testing/x86-gpu-sec2-unlock-trace-2026-04-17.md`. This directory
holds only the reproducible pieces — raw `*.trace` dumps (tens of MB)
are gitignored and regenerated by running the capture scripts.

## Files

| File | Purpose |
|---|---|
| `sec2_peek.c` | 60-line `/dev/mem` BAR0 reader. Build with `gcc -O2 -o sec2_peek sec2_peek.c` on the target box. |
| `capture.sh` | v1 — simple `mmiotrace` run. Buffer overflowed; kept for history. |
| `capture_v3.sh` | v3 — 256 MB ring buffer, still overflowed. |
| `capture_v4.sh` | v4 — stop-on-first-dmesg-match (triggered too early, before unlock). |
| `capture_v5.sh` | v5 — stop on `fb: NNNN MiB`, 1 GB ring buffer, pre/post SEC2 probe. Usable. |
| `kprobe_acr.sh` | bpftrace on nvkm ACR / FWSEC / VBIOS functions + sub-ms CPUCTL sampler. Reveals the unlock happens outside the probed functions. |
| `nouveau-dmesg-acr.txt`, `sec2-probe-acr.log`, `sec2-pre/post-nouveau*.txt`, `bpftrace-acr.out` | Small text artefacts kept as evidence supporting the findings doc. |

## Rerun

From the dev host:

```bash
# Claim test-pc, boot to Linux, SSH in.
scp sec2_peek.c capture_v5.sh kprobe_acr.sh root@192.168.4.136:/root/
ssh root@192.168.4.136 'cd /root && gcc -O2 -o sec2_peek sec2_peek.c && chmod +x *.sh'
ssh root@192.168.4.136 /root/capture_v5.sh          # produces nouveau-mmio.trace etc.
scp root@192.168.4.136:/root/nouveau-mmio.trace ./  # pull back for offline analysis
```

Invariants the scripts rely on: GPU at PCI `0000:01:00.0`, BAR0 phys
`0x53000000` / size `0x01000000`. Both come from `/sys/bus/pci/...`
and are recomputed at runtime, so a different host is fine as long as
the first BAR of the GPU is at least 16 MB.
